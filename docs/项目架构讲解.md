# CyberVerseSecondDev 项目架构讲解

> 面向面试的完整项目分析：景区导览服务 AI 数字人

---

## 一、项目定位

基于 CyberVerse 开源数字人框架的**二次开发**，构建"景区导览服务 AI 数字人"

**核心价值**：一张照片 + 一段语音 = 一个能看、能听、能说的景区导游数字人。

## 三、分层架构详解

### 3.1 前端层（Vue 3 + Vite）

**游客端**：
- `ScenicLandingPage.vue` — 景区入口页（品牌展示、导游选择、景点/路线浏览）
- `SessionPage.vue` — 实时对话页（LiveKit/Direct WebRTC 音视频）
- `ChatPanel.vue` + `ScenicCard.vue` — 对话面板 + 结构化卡片渲染

**管理端**：
- `AttractionManagePage.vue` — 景点 CRUD
- `RouteManagePage.vue` — 路线 CRUD
- `DashboardPage.vue` — 数据大屏（ECharts）
- `SessionLogPage.vue` — 对话日志查看
- `ReportPage.vue` — 感受度报告
- `CharacterEditPage.vue` — 角色编辑（扩展景区字段）

### 3.2 Go API/Orchestrator 层

**核心职责**：HTTP 路由 + 会话编排 + 数据持久化 + WebSocket 推送

| 模块 | 路径 | 职责 |
|------|------|------|
| `orchestrator/` | 会话生命周期管理 | 创建/销毁会话、驱动语音管线、双写对话日志、LLM 上下文注入 |
| `scenic/` | 景区业务数据层 | attractions/routes/sessions/conversation_logs/reports 的 SQLite CRUD |
| `api/` | REST 路由层 | 17 个新端点（景点/路线/会话分析/报告） |
| `ws/` | WebSocket Hub | 实时事件推送（任务状态、对话消息） |
| `character/` | 角色存储 | 文件系统存储，扩展 scenic_category/scenic_system_prompt/recommended_routes |
| `agenttask/` | SubAgent 任务 | SQLite 投影存储 + 任务生命周期管理 |
| `direct/` | P2P WebRTC | Pion 库 + 嵌入式 TURN 服务器 |
| `livekit/` | SFU 模式 | LiveKit 房间管理 |
| `rag/` | RAG 客户端 | 知识库文档管理（sources.json + 文件存储） |

### 3.3 Python Inference 层

**核心职责**：AI 模型推理 + 工具执行 + RAG 检索

| 模块 | 路径 | 职责 |
|------|------|------|
| `persona_agent.py` | PersonaAgent 编排 | 包装 omni provider，调度工具，管理 SubAgent |
| `plugins/voice_llm/` | 语音 LLM | Qwen-Omni 实时语音、Doubao 实时语音 |
| `plugins/avatar/` | 数字人驱动 | FlashHead（快速）、LiveAct（高质量） |
| `plugins/llm/` | 文本 LLM | 通用文本生成 |
| `plugins/tts/` | 语音合成 | 文本转语音 |
| `plugins/asr/` | 语音识别 | 语音转文本 |
| `rag/engine.py` | RAG 引擎 | LangChain + Chroma 向量检索 |
| `services/` | gRPC 服务 | 每个模块一个 gRPC service |

## 四、核心业务模块

### 4.1 景区数据管理

```
cyberverse.db (SQLite)
├── attractions        景点表（id, name, description, category, location, tags）
├── routes             路线表（id, name, duration, difficulty, tags）
├── route_steps        路线途经点（route_id, attraction_id, order, highlight）
├── sessions           会话表（id, character_id, started_at, ended_at, sentiment）
├── conversation_logs  对话日志（session_id, turn_seq, role, content）
└── reports            感受度报告
```

### 4.2 角色系统扩展

```go
type Character struct {
    // ... 现有字段 ...
    ScenicCategory    string   `json:"scenic_category,omitempty"`     // 导游/讲解员/客服
    ScenicSystemPrompt string  `json:"scenic_system_prompt,omitempty"` // 景区专属人设
    RecommendedRoutes []string `json:"recommended_routes,omitempty"`  // 推荐路线 ID
}
```

### 4.3 RAG 知识库系统

**双层知识体系**：

| 层级 | 存储 | 用途 |
|------|------|------|
| 结构化数据 | SQLite (attractions/routes) | 管理端展示、路线规划、工具调用返回 |
| 非结构化知识 | Chroma 向量库 + 源文件 | RAG 检索——数字人回答游客问题时的上下文来源 |

**RAG 流程**：
```
用户提问 → PersonaAgent 调用 retrieve_character_knowledge
  → RAGEngine.search()
  → Chroma similarity_search_with_score()
  → 返回 Top-K 相关文档片段
  → 注入 LLM 上下文
  → 数字人基于检索结果回答
```

**RAG 配置**：
- chunk_size: 900 字符
- chunk_overlap: 120 字符
- top_k: 5
- min_score: 0.25
- 向量库: Chroma (per-character 隔离)
- Embedding: Qwen text-embedding-v4 或 OpenAI text-embedding-3-small

### 4.4 记忆系统（对话历史）

**CyberVerse 的"记忆"是会话级对话历史**，不是 DeepTutor 那样的长期记忆系统：

```
会话级记忆：
┌─────────────────────────────────────────────────────────┐
│ Session.History []ChatMessage                           │
│   - 每轮对话的 user/assistant 消息                       │
│   - 会话结束时持久化到 cyberverse.db                      │
│   - 下次会话不自动加载（session-based，非 user-based）    │
└─────────────────────────────────────────────────────────┘

LLM 上下文注入：
┌─────────────────────────────────────────────────────────┐
│ orchestrator.buildLLMContext()                          │
│   1. 全局输出规范（回复长度、表达风格、内容质量）         │
│   2. 角色设定（persona prompt）                          │
│   3. 景区运营数据（景点列表 + 路线摘要）                 │
│   4. RAG 检索结果（相关知识片段）                        │
│   5. 最近 N 轮对话历史                                  │
└─────────────────────────────────────────────────────────┘
```

**与 DeepTutor 的区别**：

| 维度 | DeepTutor | CyberVerseSecondDev |
|------|-----------|---------------------|
| 记忆层级 | L0/L1/L2 三层记忆 | 仅会话级 History |
| 持久化 | profile.json + knowledge entries | cyberverse.db sessions + conversation_logs |
| 跨会话 | 支持（L2 长期记忆） | 不支持（session-based） |
| 用户画像 | AbilityProfile（掌握度、薄弱点） | 无（景区场景不需要） |
| 记忆消费 | LLM prompt 注入 + 规则引擎 | 仅 LLM 上下文注入 |

## 五、用户核心行为处理链路

### 5.1 游客语音对话链路（核心链路）

```
游客说话
  │
  ▼
[WebRTC] 音频流 → Go orchestrator
  │
  ▼
[gRPC] → Python inference server
  │
  ▼
[Qwen-Omni] 端到端语音处理（ASR + LLM + TTS 一体化）
  │
  ├─ 普通对话 → 直接生成语音回复
  │
  └─ 需要工具调用 → PersonaAgent 判断
       │
       ├─ get_attractions → HTTP → Go /api/v1/attractions → 返回景点列表
       ├─ get_routes → HTTP → Go /api/v1/routes → 返回路线列表
       ├─ get_attraction_detail → HTTP → Go /api/v1/attractions/:id → 返回详情
       ├─ retrieve_character_knowledge → RAG → Chroma 检索 → 返回相关知识
       └─ create_task → SubAgent 异步执行（搜索/调研/报告）
       │
       ▼
  PersonaAgent 组织回答 → 生成语音回复
  │
  ▼
[WebRTC] 音频流 → 游客听到回复
  │
  ▼
[Go] 同时写入 cyberverse.db（双写：文件 + SQLite）
```

### 5.2 游客拍照识景链路

```
游客拍照上传
  │
  ▼
[WebSocket] 图片 base64 → Go orchestrator
  │
  ▼
[gRPC] → Python inference server
  │
  ▼
[PersonaAgent] 识别到图片 → 调用 recognize_scenic_spot 工具
  │
  ├─ 调用 Qwen-VL API（多模态模型）→ 识别景点 + 生成介绍
  │
  └─ 同时查询 attractions 表 → 尝试匹配已知景点
  │
  ▼
返回景点介绍文本 + 结构化信息
  │
  ▼
[WebRTC] 语音回复 + [WebSocket] 结构化卡片
```

### 5.3 管理端数据大屏链路

```
管理员打开数据大屏
  │
  ▼
[Vue] GET /api/v1/analytics/dashboard
  │
  ▼
[Go] scenic.DashboardStore.GetDashboard()
  │
  ├─ 今日服务人次：SELECT COUNT(*) FROM sessions WHERE date = today
  ├─ 平均对话时长：SELECT AVG(duration_s) FROM sessions
  ├─ 热门问题 Top10：SELECT content, COUNT(*) FROM conversation_logs WHERE role='user' GROUP BY content
  ├─ 满意度分布：SELECT sentiment, COUNT(*) FROM sessions GROUP BY sentiment
  └─ 活跃时段分布：按小时聚合
  │
  ▼
[Vue] ECharts 渲染图表
```

### 5.4 感受度报告生成链路

```
管理员点击"生成报告"
  │
  ▼
[Vue] POST /api/v1/reports/generate
  │
  ▼
[Go] 创建 SubAgent 任务（status=queued）
  │
  ▼
[Python] SubAgent 异步执行
  │
  ├─ 读取 cyberverse.db 对话日志
  ├─ 调用 LLM 分析对话情感、满意度、常见问题
  ├─ 生成结构化报告 JSON
  └─ 写入 data/reports/<report_id>/
  │
  ▼
[Go] 更新任务状态 → WebSocket 推送 → 前端实时更新
```

## 六、关键技术设计决策

### 6.1 双写架构（Best-Effort）

```
对话消息到达 → persistSessionConversation()
  ├─ 1. 写文件（原有逻辑，不动）→ 保证主链路稳定
  └─ 2. syncSessionToDB()（best-effort）→ DB 失败不影响主链路
       ├─ 首次：CreateSession → 记录 dbSessionID
       └─ 每次：只写 dbSyncedCount 之后的新增消息
```

**设计理由**：比赛场景下，稳定性优先。SQLite 写入失败不应阻断语音对话。

### 6.2 PersonaAgent 工具链（零额外 LLM 调用）

```
PersonaAgent 工具调用 → httpx HTTP → Go REST API → SQLite → 返回 JSON
```

**整条链路中没有额外 LLM 调用**。所有 LLM 调用都是 PersonaAgent 和已有语音链路的正常运行。

### 6.3 景区上下文注入

```go
func (o *Orchestrator) buildScenicContext() string {
    // 从 cyberverse.db 读取景点列表 + 路线
    // 格式化为结构化摘要
    // 注入到 LLM system_prompt
}
```

**注入位置**：角色设定之后、RAG 之前。保证数字人"知道"景区有哪些景点和路线。

### 6.4 情感标注（会话结束时批量分析）

```
会话结束 → OnSessionEnd
  → go orch.AnalyzeSessionSentiment(dbSID, history)
  → 读取该 session 所有 user 消息
  → 一次 LLM 调用判断整体情感极性（positive/neutral/negative）
  → UPDATE sessions SET sentiment=? WHERE id=?
```

**设计理由**：不在每轮对话后触发 LLM，节省 token。一个 session 只需 1 次额外 LLM 调用。

## 七、与 DeepTutor 的技术对比

| 维度 | DeepTutor | CyberVerseSecondDev |
|------|-----------|---------------------|
| 语言 | Python 全栈 | Go + Python + Vue 三语言 |
| 架构 | 单进程 Agent Loop | 三进程协作（gRPC + WebSocket） |
| 数据库 | 文件系统 (JSON/MD) | SQLite (cyberverse.db) |
| 实时通信 | SSE 流式 | WebRTC 音视频 + WebSocket |
| 核心能力 | RAG + 记忆系统 | 数字人语音交互 + 视觉输入 |
| RAG 实现 | LlamaIndex + Qdrant + BM25 | LangChain + Chroma |
| 记忆系统 | L0/L1/L2 三层 | 仅会话级 History |
| 业务复杂度 | ExamSprint 多业务判断 | 景区导览相对直接 |
| 扩展方式 | 注册式扩展（工具注册） | 插件式架构（FQCN 加载） |

## 八、项目亮点总结

1. **三语言协作架构**：Go（高性能 API）+ Python（AI 推理）+ Vue（前端），通过 gRPC + WebSocket 解耦
2. **插件式架构**：所有 AI 能力（avatar/voice_llm/llm/tts/asr）都是可替换插件，通过 YAML 配置切换
3. **双写 Best-Effort**：对话日志双写到文件 + SQLite，DB 失败不影响主链路
4. **PersonaAgent 工具链**：工具调用走 HTTP → Go → SQLite，零额外 LLM 消耗
5. **景区上下文注入**：景点/路线数据自动注入 LLM system_prompt，数字人"知道"景区信息
6. **WebRTC 实时音视频**：支持 P2P Direct 和 LiveKit SFU 两种模式，NAT 穿透
